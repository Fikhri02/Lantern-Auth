# Lantern Auth — Plan Roadmap

**Spec:** `docs/superpowers/specs/2026-10-01-lantern-auth-design.md`

The spec is built in five plans. Each ends in working, tested software, and each later plan is written
**after** the previous one is finished, so it can use what the earlier build taught (especially the
spikes in §12 of the spec).

| # | Plan | Scenarios | Spec sections | Depends on | Status |
|---|---|---|---|---|---|
| 1 | **Foundation**: repo, Keycloak image and realm, hostname spike, API with every role policy, deactivation check, staff management | C, F, I (staff part) | §2, §4 (except flows and themes), §5.3–5.5, §8, §12.1 | — | Done (merged) |
| 2 | **Till backend**: PIN plugin (credential storage, three flow steps, account limit, admin resource), persistent outlet login, sales and receipts, till-account and cashier endpoints | D, E, I (cashier and till part) | §4.5 till client, §5.5 cashier and till rows, §6 (Keycloak and API side), §7 till rows, §12.2–12.3 | 1 | Done (merged) |
| 3 | **Till app**: Blazor Web Till with persistent till registration (encrypted, on disk), PIN pad, idle lock, ringing sales, receipts, "Sign out this till" | D, E (user-facing) | §6.1 steps 4–6, §6.2 till side, §6.5 (incl. dropping cashiers when the outlet refresh fails), §7 till messages | 2 | Planned |
| 4 | **Web apps**: `Lantern.Auth` BFF library, Back Office, Outlet Admin (including the Tills page), back-channel logout, MFA, deny-access flows, themes | A, B, G, H | §4.5 flow overrides, §5.1, §5.2, §5.6, §5.7, §7, §12.4 | 1, 2 | — |

app are independent subsystems, each testable on its own.
